# Code Review 零忽視與即時修復鐵律 (Zero-Tolerance Code Review Guard)

> **任務載入時機**：編寫代碼、重構功能、執行 `agentctl check` 或準備 Commit 時必讀。

---

## 1. 核心鐵律：有問題不忽視，當下立刻解決

軟體工程的技術債往往始於「這次先忽略警告，下次再修」。因此確立不可逾越之鐵律：

> **凡執行 `code-review-guard` 或 `agentctl check` 掃描出的任何警告（Warning）或錯誤（Critical），嚴禁略過、推延或視而不見，必須在當次對話中就地重構修復完畢。**

---

## 2. 五大常見代碼異味與標準重構手法

| 異味類型 | 觸發門檻 | 根因危害 | 標準即時重構手法 |
|---|---|---|---|
| **巢狀過深 `[Nesting]`** | 巢狀層級 $> 3$ 層 | 認知負荷過大、邊界分支易遺漏 | **Guard Clauses（衛語句 / Early Return）**：將防禦性檢查、例外條件置於函式最前端直接 `return` 或 `raise`，扁平化主邏輯流程。 |
| **函式過長 `[Size]`** | 函式行數 $> 40$ 行 | 職責不單一、難以編寫單元測試 | **Extract Function（提煉函式）**：依據單一職責原則（SRP），將資料提取、格式轉換、業務驗證等步驟萃取為純子函式。 |
| **參數過多 `[Params]`** | 參數個數 $> 4$ 個 | 呼叫簽章脆弱、順序易錯 | **Introduce Parameter Object（引入 DTO）**：將關聯參數封裝為不可變資料結構（Python `@dataclass(frozen=True)` 或 TypeScript `interface`）。 |
| **模組日誌缺漏 `[Logging]`** | 有函式但無 logger | 執行期不可觀測、排查盲區 | 在模組開頭統一宣告 `logger = logging.getLogger(__name__)`，並於關鍵邊界與例外處記錄日誌。 |
| **註解標頭缺漏 `[Comments]`** | 缺模組用途、函式或參數說明 | 維護者與 AI 失去上下文理解 | 依據 Google 風格補齊：模組開頭用途摘要、函式單行功能、所有參數的 `Args:`（開放 Web 工具支援 `:param`）與回傳值 `Returns:`。 |

---

## 3. 合法例外處理機制

若特定程式碼因架構限制或第三方框架綁定（例如由工具自動產生的資料庫遷移腳本、大型 CLI 參數解析器）確實存在指標超出情況：
1. **合法排除標註**：在 `.agents/project.toml` 中的 `[quality]` 適度設定合法容錯門檻，或由專案規則明文豁免（如 `logger_exempt_layers`）。
2. **禁止隱蔽略過**：嚴禁用假註解或隨意註解掉檢查器來欺騙檢查工具。
3. **保持提交純淨**：確保進入 Git 提交紀錄的每一行代碼皆經得起自動化工具檢驗。
