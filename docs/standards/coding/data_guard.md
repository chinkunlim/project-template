# 資料寫入與變異防護鐵律 (Data Mutation Guard)

> **任務載入時機**：修改、排版、批次寫入任何資料（資料庫、JSON/YAML、Markdown 筆記正文）時必讀。

---

## 1. 核心精神與適用範疇

Agent 在進行任何「資料內容」寫入、格式化排版或結構遷移時，必須與程式碼修改一樣，嚴格遵守 TDD、SOLID、Atomic 鐵律，避免誤傷、刪減或污染不需改動的既有內容。

---

## 2. 格式與內容嚴格隔離原則 (Format vs. Content Isolation)

- **排版變更**：當任務是調整 CSS、Markdown 標題層級、排版縮排、表格美化或欄位對齊時，**嚴禁修改、精簡或刪改實質文本內容**。
  > 鐵律：**「改格式不改文字，改文字不動格式」**。
- **正文編輯**：當任務是修正錯別字、補充段落或更新知識點時，維持現有排版樣式，不隨意套用未經確認的排版重構。

---

## 3. 防呆校驗與指紋驗證 (Fingerprint Verification)

1. **字元級零刪字稽核**：
   - 在批次修改教材或筆記正文時，必須在寫入前後比對去除空白與格式標籤後的字元序列。
   - 若有效字元數發生未預期的縮減或漂移，必須立即中止寫入並告警。
2. **文字雜湊與區塊比對 (Hash / AST Guard)**：
   - 局部修改前，需比對目標區塊的哈希或 AST 結構，確保精確命中目標段落，禁止以大範圍盲目正則覆蓋造成周邊資料損毀。
3. **備份與回滾機制**：
   - 批次寫入或破壞性資料更新前，必須留存原檔快照（Snapshot）或歷史版本，確保一旦發現異常可無損即時還原。
